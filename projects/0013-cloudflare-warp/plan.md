# 計画: Cloudflare WARP の設定方法（Issue #13）

## 目的（再定義）
Cloudflare WARP（Cloudflare One クライアント）でゼロトラストネットワークを新規構築するために、管理側（Cloudflare Zero Trust ダッシュボード）とクライアント側（端末）の双方で必要な設定項目と手順を、公式情報を一次根拠として整理した報告書（`report.md`）を作る。

## 受入基準
| ID | 基準 | 重み |
| --- | --- | --- |
| a1 | サーバ側の前提設定（チーム名・組織作成、IdP連携、Device enrollment 権限）が、設定項目名と手順つきで記載されている | 3 |
| a2 | サーバ側のトラフィック制御設定（デバイスプロファイル、Split Tunnels、Gateway のネットワーク/DNS/HTTPポリシー、Access・Cloudflare Tunnel による社内アプリ接続）について、各項目の「目的・設定場所・設定値の例」まで記載されている | 3 |
| a3 | クライアント側の設定（対応OS別の導入、Zero Trust への登録手順、MDM 配布時に指定する具体的パラメータ名と値の種類、ルート証明書配布）が記載されている | 3 |
| a4 | サーバ側とクライアント側の設定の対応関係が表で示されている | 2 |
| a5 | すべての設定項目に公式ドキュメントURLと取得日が付いている | 2 |
| a6 | 構築後の動作確認方法（接続状態、ポリシー反映の確認）が記載されている | 1 |
| a7 | 公式に記述が無かった論点と、公式と非公式の相違点が、専用の節に一覧化されている（情報なしの場合も探した範囲を書く） | 1 |

## 作業方針
research 用途の3段構成（公式調査 → 非公式調査 → 突き合わせ）で行う。

## 採用しなかった批評とその理由
- a7 を「公式推奨構成と一般的ユースケースの差異を『注意点』として明記」に置き換える提案: 本用途の突き合わせ規則（公式と非公式の相違を残す）と重複するため置換せず、a7 を「専用の節に一覧化」と検証可能な形に書き換える形で部分採用した。
