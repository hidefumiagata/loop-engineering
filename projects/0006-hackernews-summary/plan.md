# 計画 — Issue #6 Hacker News Top10 の日本語要約

## 目的（再定義）

Hacker News トップページの取得時点の上位10件について、リンク先の記事を実際に読み、
記事ごとに日本語500文字以内の要約を作る。10件すべてに要約があることが完了条件。

## 受入基準

| ID | 基準 | 重み |
| --- | --- | --- |
| a1 | HN 上位10件を取得日時付きで順位順に列挙し、各件のタイトル・記事URL・HNスコアを明記している | 3 |
| a2 | 10件すべてに日本語の要約がある | 3 |
| a3 | 各要約が日本語500文字以内である。文字数は Unicode のコードポイント数（全角・半角・空白・記号を各1字）で数え、`report.md` に各件の文字数を載せる | 3 |
| a4 | 各要約の固有名詞・数値・日付は、記事本文に書かれているものだけを使う。記事に無い推測は「〜と思われる」等で推測と明示する | 2 |
| a5 | 各要約に、記事の主要な主張または結論が最低1つ含まれている | 2 |
| a6 | 本文を取得できない、または要約すべき文章が無い記事（ゲーム・動画・PDF・403等）は、その理由を明記し、取れた範囲の説明に留めている | 2 |
| a7 | 各要約の出典URLと取得日が `sources.md` にある | 1 |

## 採用した批評

- a4 を「主観的」と指摘 → 固有名詞・数値・日付が本文由来であることという検証可能な形に書き直した。
- 主張・結論を含むことの基準 → a5 として採用。
- 取得失敗時の理由明記 → 既存の a6 に統合して採用。
- 文字数の数え方の曖昧さ → a3 に定義を追加。

## 採用しなかった批評とその理由

- 「事実関係の正確性や論理構成に関する具体的なチェック項目が無い」: 論理構成は検証者によって判定が割れるため基準にしない。正確性は a4（本文由来であること）で代替した。
- 「『記事本文』の定義が曖昧」: 定義を固定せず a6 で例外（取得不能・文章なし）を扱う方針にした。個別の扱いは `report.md` に注記する。

## 補足

- 「Top10」は HN 公式 API `topstories` の先頭10件（トップページの順位順）とする。取得時刻により入れ替わる。
