# 計画

## 目的の再定義
80名規模のSRE/DevOps組織で、金銭的予算なしに、社外のSRE/DevOpsイベントへの参加と（できる人の）登壇が、指名や強制ではなくメンバー自身の意思で起きる状態を作る。そのための施策を、翌週から着手できる具体性で1つの筋に絞って立案する。

## 受入基準

| ID | 重み | 基準 |
| --- | --- | --- |
| a1 | 3 | 施策が「誰が・いつ・何を・どの順で」やるかの手順として書かれており、責任者の役割と、開始から最初の成果までの期間が明記されている |
| a2 | 3 | 金銭的予算ゼロの前提で成立し、必要な資源（時間・既存の場・人）が列挙され、有償のものに依存していない |
| a3 | 3 | 自発的に動くための誘因として、内発的動機（スキル向上・称賛など）と外発的動機（業務時間内での参加許可・評価への組み込みなど）の具体的な仕組みが、それぞれ明記されている |
| a4 | 2 | 参加と登壇の両方について、初心者向け／経験者向けの入口が段階として分けて設計されている |
| a5 | 2 | 運用負荷が、運用者の週あたり合計5時間以内であることが工数見積で示されている |
| a6 | 2 | 施策が失敗する条件が3件以上挙げられ、それぞれに早期検知の兆候がある |
| a7 | 1 | 1か月以内に試せる最小の試行案があり、成功／失敗の判定指標が書かれている |
| a8 | 1 | 検討したが採用しなかった代替案と理由が記録されている |

## 採用しなかった批評とその理由
なし。Gemini の2つの提案（a3 を設計上の仕組みの明記に置き換える、a5 に週5時間の閾値を置く）はどちらも取り込んだ。
