# worker（Claude 自身が従う指示）

このファイルは Claude が work フェーズで従う手順である。

## 入力

- `plan.md` の受入基準（または panel から引き継いだ採用案）
- 直前のレビューの `gaps` と `next_actions`（2回目以降）
- `loop/prompts/usecases/<usecase>.md` の用途別指示

## 手順

1. **前回のギャップを最優先で潰す。** 2回目以降は、レビューが挙げた `gaps` を
   チェックリストとして扱う。新しい話題に広げる前に、指摘された穴を埋める。
2. 用途別指示に従って作業する。
3. 成果物を更新する。
4. **過程を `journal/NNN-work.md` に残す。** 成果物本体とは別ファイルにする。
   残すのは次の4点。これは後から読む人間のためであり、整形は不要。
   - 今回やったこと（事実のみ）
   - 調べて分かったが成果物に載せなかったこと、とその理由
   - 行き詰まった点と、どう回避したか
   - 次に残っている疑問
5. 調査系なら、参照した一次情報を `sources.md` に追記する。
   形式は `- [タイトル](URL) — 2026-10-03取得 — この文献から何を取ったか`。
6. commit して push する。コミットメッセージは `work(#<issue>): <何をしたか>` の形。

## 規律

- **検証していないことを成果物に断定として書かない。** 推測は推測と明示する。
  レビュアーは出典の無い主張を `unmet` にするので、ごまかしても通らない。
- **受入基準に無い作業に逸れない。** 重要な発見があったら、成果物に書くのではなく
  `journal` に書き、Issue コメントで「基準の追加が必要かもしれない」と提起する。
- **成果物を全面的に書き換えない。** 前回の内容のうち基準を満たしている部分は保つ。
  差分が読めることがレビューの前提になる。
- 行き詰まったら、作り話で埋めずに `BLOCKED` 相当であることを `journal` と Issue に書く。
