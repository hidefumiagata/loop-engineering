## 1. Qwen 3.8 Flash Next（125B）を RTX 4090 で毎秒100トークンで動かす

- **元記事**: [Run Qwen 3.8 Flash Next (125B) on consumer hardware (RTX 4090) at 100T/s](https://github.com/Niko1221/Strata) — github.com — HN 433点 / コメント233件
- **HN**: <https://news.ycombinator.com/item?id=49953495>

Strata は、125B パラメータの MoE モデル Qwen3.8-Flash-Next を家庭用ゲーミングPCで動かす推論エンジン。GPU には頻繁に使う専門家（エキスパート）、RAM には全24,576個のエキスパート、CPU には溢れた計算、SSD には参照テーブルを置く分担方式で、さらに小型モデルが先読みして本体が検証する投機的デコーディングを併用する。READMEの数値は RTX 5070（12GB）で生成53〜94 tok/s、RX 9070 XT で44〜60 tok/s。必要環境は VRAM 12GB 以上、RAM 32GB 以上（推奨64GB）、空き約80GB。OpenAI・Anthropic 互換 API をローカルで提供し、画像入力にも対応する。

**議論の要点**: 最速設定は2ビット量子化とエキスパート削減で品質低下が大きいとの批判（画像の誤差が llama.cpp 比で約3倍との検証報告）と、IQ3 級なら実用上ほぼ劣化なしという擁護で割れている。

## 2. 世界中の灯台の地図

- **元記事**: [A map of every lighthouse](https://mapped.earth/lighthouses/world) — mapped.earth — HN 114点 / コメント55件
- **HN**: <https://news.ycombinator.com/item?id=49933461>

「海図に載る世界中のすべての灯を、実際の点滅周期で」表示するインタラクティブな地球儀マップ。スコットランド、ブルターニュ、ニューイングランド、日本、ノルウェー、ケープタウンなど地域ごとのプリセット表示があり、同サイトの河川・降雨・UV・雷などの地図群の一部として提供されている。データの出典は読んだページ上では明記されておらず、灯台の総数も確認できなかった。灯の点滅を実周期で再現するという見た目の面白さが売りの作品である。

**議論の要点**: 位置の誤りや、航路標識・ブイなど灯台でないものの混入（「実在の10倍ほど表示される」との声）、ピンチ操作の不具合、CPU負荷の高さが指摘された。データは OpenStreetMap 由来で、「vibe-coded」だという批判もある。

## 4. Jane Street の ASIC パズルの結果発表

- **元記事**: [Results from the ASIC puzzle](https://blog.janestreet.com/asic-puzzle-results/) — blog.janestreet.com — HN 35点 / コメント7件
- **HN**: <https://news.ycombinator.com/item?id=49934078>

チップの物理レイアウト（GDS）だけを渡し、ネットリストも信号名も無しに「このチップは何をするか」を当てさせた逆解析パズルの結果報告。30か国以上から約400件の提出があった。正解は 11×11 の Star Battle（各行・列・領域に星を2つ、斜めを含め隣接禁止）の検証回路で、2ビットカウンタ、121ビットROM、隣接検出の遅延線、LFSRによる出力難読化で構成される。解法は KLayout などによるネットリスト抽出、シミュレータ自作、成功信号からの逆追跡、SAT ソルバなど多様。複数の独立実装を突き合わせた参加者が、波形だけでは見えないバグを見つけたという教訓も語られる。AI は道具作りを速めたが、理解する喜びの代わりにはならなかったとまとめている。

**議論の要点**: パズル自体よりも、高頻度取引（HFT）の社会的意義や Jane Street が HFT 企業かどうかをめぐる議論が大半を占めた。

## 6. Glashütte Trash Clock — ゴミで作った30分の振り子時計

- **元記事**: [Glashütte Trash Clock](https://niklasroy.com/gtc/) — niklasroy.com — HN 137点 / コメント16件
- **HN**: <https://news.ycombinator.com/item?id=49930439>

アーティストの Niklas Roy が、2026年にドイツ・グラスヒュッテの NOMOS でのレジデンシー中に、廃材だけで作った動く機械式時計。約30分動き、秒と分を表示し、正時にはガラス瓶のゴングを鳴らす。振り子はホイヘンスの原理に従い、木の定規とペットボトルで作った秒振り子で、実測で1秒あたり1.004秒（誤差±0.4%）。脱進機の爪は曲げた金属棒、30歯の脱進輪はクリップ製。動力は金属くずを入れた塗料缶の錘で、分針へは歯車ではなく摩擦円盤で減速する。錘が尽きる直前に「NOW」と「NEVER」と書かれた運命の輪が回る遊びも付く。

**議論の要点**: 「理論より先に作る」姿勢への称賛と、閏秒・閏秒スミアリングの脱線、グラスヒュッテの時計産業史が主な話題になった。

## 9. ncurses の terminfo で動くミンスキー機械

- **元記事**: [A Minsky machine in ncurses terminfo](https://seriot.ch/computation/terminfo/) — seriot.ch — HN 24点 / コメント6件
- **HN**: <https://news.ycombinator.com/item?id=49935250>

端末の機能データベースである terminfo が、実は2カウンタのミンスキー機械を実装できる小さなプログラミング言語だと示した記事。レジスタ A・B と、命令位置を保持する Z を terminfo の永続変数で表し、算術（`%+` `%-`）、引数参照、条件分岐（`%?…%t…%e…%;`）を使って、ケーパビリティを1回展開するたびに機械語を1命令実行する。4+9 を計算する加算機やフィボナッチ生成器の実例があり、`/usr/bin/top` の画面再描画を外部クロックにして動かす「寄生型フィボナッチ」も紹介されている。ncurses を使うプロセスに計算が寄生できることの含意も示す。

**議論の要点**: terminfo という固定DBの設計がいまや時代遅れではないか、各端末が xterm-256color を名乗ってしまう問題が話題になった。記事が人手か生成かを問う声もあった。
